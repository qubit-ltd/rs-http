# rs-llmsdk 消费者升级 qubit-http 0.16 兼容性核查

## 结论

在隔离副本中，将两个消费者的直接约束由 `qubit-http = "^0.15"` 临时改为 `"^0.16"`，并 patch 到本轮 rs-http 工作树后，core 与 OpenAI provider 的全目标检查和计划指定的 focused tests 均通过。没有复现需要修复的 rs-http 公共 API 或运行时缺陷。

实际消费者仍声明 `^0.15`，因此其依赖清单在计划升级时须改为 `^0.16` 并提交相应 Cargo.lock 更新。本核查没有修改或提交两个消费者的正式仓库。

## 仓库与依赖基线

| 项目 | 实际 package | 起始分支 / HEAD | 起始状态 | 原直接约束 / 锁定版本 |
| --- | --- | --- | --- | --- |
| `/data/working/qubit/rust-llmsdk/rs-llmsdk-core` | `llmsdk-core 0.3.0` | `dev-starfish` / `0c7341741421dcdd029818225b5ddf33100fe532` | 干净 | `^0.15` / `qubit-http 0.15.1` |
| `/data/working/qubit/rust-llmsdk/rs-llmsdk-provider-openai` | `llmsdk-provider-openai 0.2.0` | `main` / `1231c34dc5989910ddcffdff9d7a738381b03323` | 干净 | `^0.15` / `qubit-http 0.15.1` |

实际验证副本位于 `/data/working/qubit/rust-llmsdk-http016-validation/`，由以上两个仓库的 detached worktree 组成；`rs-llmsdk-agent` 仅以原目录符号链接满足 provider 的相邻路径依赖。原始仓库分支和工作区保持不变。

副本中的两个 crate 清单只做验证用修改：直接约束改为 `^0.16`，并在各自 manifest 加入：

```toml
[patch.crates-io]
qubit-http = { path = "/data/working/qubit/rust-common/rs-http-review-20261104" }
```

Cargo.lock 仅在隔离副本中更新。两处 `cargo tree -i qubit-http` 均将唯一的 `qubit-http` 解析到上述本地工作树版本 `0.16.0`；provider 的依赖树同时显示 core 与 provider 通过同一个本地 `qubit-http`。`cargo tree -d` 显示消费者原有依赖和 0.16 依赖间存在若干不同版本，例如 `qubit-config` 0.14.3/0.15.0、`qubit-json` 0.10.0/0.12.1、`qubit-redact` 0.9.0/0.10.0、`qubit-datatype` 0.14.0/0.15.2，以及 `qubit-budget`、`qubit-value` 的旧/新版本。所有目标均通过编译与测试；本轮没有证据表明这些重复类型穿过消费者与 HTTP API 边界，也未为此调整无关的直接依赖。

## 行为覆盖矩阵

| 场景 | 现有消费者证据 |
| --- | --- |
| 普通 JSON 成功 | `openai_chat_engine_tests::test_sync_generation_normalizes_usage_and_metadata`；请求/响应由本地 mock server 处理 |
| SDK 调用级重试与 HTTP 外层重试分工 | `openai_chat_engine_tests::test_summary_http_retry_preserves_partial_usage` 与 `openai_responses_engine_tests::test_summary_http_retry_preserves_partial_usage` 各让 mock 返回 429 后 200；`take_request()` 确认对应两个 provider call 各发送一次。Chat/Responses client 构造器分别调用 `disable_retry()`（`src/chat/openai_chat_client.rs`、`src/chat/openai_responses_client.rs`） |
| Chat `[DONE]` 生命周期 | `openai_chat_client_tests::test_chat_stream_rejects_done_marker_without_choice_finish_reason`；另有正常 done 流用例 |
| Responses EOF 容忍和业务终态 | `openai_responses_client.rs` 显式配置 `SseCompletionPolicy::AllowEof`；`openai_responses_engine_tests::test_responses_stream_requires_completed_and_emits_text_delta` 与 `test_responses_truncated_stream_is_terminal_error` 验证业务完成和截断处理 |
| JSON/SSE 无效负载及截断 | `openai_chat_client_tests::test_client_reports_malformed_json_and_stream_payloads`、`openai_chat_engine_tests::test_stream_reports_invalid_sse_json_as_terminal_error`、`openai_responses_engine_tests::test_responses_truncated_stream_is_terminal_error` |
| 客户端重建保留 request interceptor | 原有 core 用例 `remote_engine_parts_tests::test_remote_engine_parts_rebuild_keeps_request_interceptor`，重建 timeout 与 retry 设置后均断言 interceptor 仍生效 |
| 客户端重建保留 async header injector | 原消费者缺少该直接断言；只在隔离副本追加以下最小回归，验证两次重建后 injector 仍能短路请求。没有连接真实外网： |

```rust
#[tokio::test]
async fn test_remote_engine_parts_rebuild_keeps_async_header_injector() {
    let provider = Arc::new(StaticCredentialProvider::new(CredentialBundle::api_key("sk-test")));
    let mut client = HttpClient::builder().create_default().expect("HTTP client");
    client.add_async_header_injector(AsyncHttpHeaderInjector::new(|_headers: &mut http::HeaderMap| {
        Box::pin(async { Err(HttpError::other("async injector marker")) })
    }));
    let mut parts = RemoteEngineParts::new(provider)
        .expect("remote parts")
        .with_http_client(client);

    parts
        .set_timeout_options(HttpTimeoutOptions::default())
        .expect("timeout options");
    let request = parts
        .http_client()
        .request(http::Method::GET, "http://127.0.0.1:9/relative")
        .build();
    let error = parts
        .http_client()
        .execute(request)
        .await
        .expect_err("async injector should still reject the request");
    assert!(error.to_string().contains("async injector marker"));

    let mut options = parts.http_options().clone();
    options.retry = retry_options(1);
    parts.set_http_options(options).expect("HTTP options");
    let request = parts
        .http_client()
        .request(http::Method::GET, "http://127.0.0.1:9/relative")
        .build();
    let error = parts
        .http_client()
        .execute(request)
        .await
        .expect_err("async injector should survive retry configuration");
    assert!(error.to_string().contains("async injector marker"));
}
```

## 最终判断

HTTP-003 通过：实际 consumer manifests 仍需在正式升级时把 `qubit-http` 直接约束更新为 `^0.16`；隔离副本中的编译、解析和 focused tests 通过。没有发现需要修改 rs-http 的公共签名、运行时实现或正式下游源码的 0.16 兼容性缺陷。本轮不发布 crate，也不改写消费者分支。
