## 3. 方案比较与选择

选择在现有所有权和解码管线内修复：保持 `HttpResponse` 三态、SSE 字节→行→记录→JSON 的分层，以及独立重连执行器。局部状态和诊断修正即可解决已确认问题，成本和迁移范围最小。

未选择新增 SSE 宽松/严格 framing 开关：它会把 EOF 兼容策略传播到 options、配置解析、response 和 reconnect API，并扩大测试矩阵。当前目标是纠正已确认的 framing 缺陷，尚无证据证明需要长期保留残帧派发。

未选择替换 SSE 解码器或响应状态架构：会触及错误映射、限额、取消和重连边界，超过七项问题所需范围。

## 4. HTTP-001：独立记录两类截断

保留 `read_error_body_preview` 的返回形状 `HttpResult<(String, Bytes, bool)>`；最后的 bool 仅表示原始保留 body 不完整。

内部以两个明确含义的标志替代共用 `truncated`：

- `preview_truncated`：有实际字节未纳入 preview；只供脱敏渲染。
- `raw_truncated`：有实际字节未纳入 raw，或读取错误/超时使完整性无法保证；只供 `HttpStatusResponse::is_truncated()`。

保持现有 capture budget，最多探测到 `max(preview_limit, raw_limit) + 1` 字节；使用饱和运算，不扩大内存上限。不根据“恰好达到上限”猜测存在更多字节：如已观察到 EOF，则该长度完整。若没有 EOF、已观察到额外字节或发生读取失败，则按对应内容不完整处理。

预览上限小于 raw 时，preview 截断不得污染 raw；raw 上限小于 preview 时，raw 截断不得反向污染 preview。读取错误/超时保持现有错误预览占位和 raw 不完整语义，取消仍返回 `Cancelled`。服务端 Content-Length 可提供额外不完整证据，不能覆盖已观察到的截断事实或传输失败。

缓冲响应路径同样遵循两类限额的独立含义，不新增公开字段。保留方法、URL、状态、Retry-After 和错误 source 的既有契约。

下游依据：`rs-llmsdk-provider-openai/src/chat/openai_error_classifier.rs::map_http_error` 只解析 `!is_truncated()` 的 JSON。当前其依赖声明是 `qubit-http ^0.15`；本轮不修改下游清单，也不把源码阅读描述成已经接入本地 0.16。未来手工集成核查须明确实际绑定版本。

## 5. HTTP-004：缓存流不移交缓存所有权

`HttpResponse::stream(&mut self) -> HttpResult<HttpByteStream>` 签名保持不变。在执行 destructive state replacement 之前识别 `Buffered`：克隆其 `Bytes`，返回一次性单块流，响应自身仍为 `Buffered`。

Backend 分支仍以 `StreamingTaken` 移交后端 body，仅能取得一次。既有 body read failure 与取消前置检查保留优先级。响应状态表：

| 初始状态 | 调用 stream 的结果 | 调用后的响应状态 |
| --- | --- | --- |
| Buffered | 克隆缓存的单块流 | Buffered |
| Backend | 带超时、取消和错误记录的后端流 | StreamingTaken |
| StreamingTaken | ResponseBodyAlreadyConsumed | StreamingTaken |

验证 `bytes → stream → bytes`、连续两次 cached stream、流尚未消费或被丢弃时读取缓存；保留 backend 单次消费和首次错误类别保持的测试。

## 6. HTTP-002：EOF 不派发残留数据帧

SSE framing 以空行完成事件。移除 EOF 分支中的 `SseRecord::Dispatch` 生成，仅空行分支可派发数据。行解码器继续提供最后一个未换行的文本片段；是否完整构成事件由 frame decoder 决定，不跨层改变普通行处理。

本次不顺手重写控制记录语义：保留当前已解析的 retry 提示与 control-only id 处理。包含未完成 data 的末帧不得派发消息，也不得因该末帧的 id 提前推进恢复游标。传输错误仍先上抛，不把它伪装成正常 EOF。控制字段其他协议差异不在此次整改范围。

| 输入结尾 | sse_messages | RequireDoneMarker 的 sse_chunks |
| --- | --- | --- |
| `data: value` 后 EOF | 无新消息 | 缺完成标记时 SseProtocol |
| `data: value\n` 后 EOF | 无新消息 | 缺完成标记时 SseProtocol |
| `data: value\n\n` | 派发一帧 | 按 JSON 和完成策略继续 |
| `data: [DONE]` 后 EOF | 不派发残帧 | 一个 SseProtocol，随后结束 |
| `data: [DONE]\n\n` | 完整消息 | 一个 Done，随后结束 |

CR 或 CRLF 组成的完整空行也有效。`AllowEof` 允许完整事件流在没有 done marker 时结束，不意味着允许派发未完成帧。

规范依据：[WHATWG SSE interpreting an event stream](https://html.spec.whatwg.org/multipage/server-sent-events.html#event-stream-interpretation)。

## 7. HTTP-005：只移除流起始的一个 BOM

在现有 line decoder 内维护首行状态，首个成功解码行只剥离一个起始 U+FEFF；之后任意位置的 U+FEFF 均作为正文保留。字节块的切分不得影响结果，空块不消耗首行状态，空的首行会消耗该状态。

最小实现允许首行暂存最多 `max_line_bytes.saturating_add(3)` 字节，再在移除 BOM 后按实际行字节数核对 `max_line_bytes`；其余行继续用现有上限。这样跨块 BOM 无需引入新的公共解析类型，且 BOM 本身不占逻辑行预算；首行临时额外空间至多三个字节。无 BOM 首行也必须在派发前执行实际上限检查，不能借此多接受三个正文字节。

在调用 `take_buffered_line` 或其私有替代 helper 时显式传入首行状态与限额，所有正常行终结和 EOF 尾行出口使用同一逻辑。非法 UTF-8 继续返回 `SseProtocol`；不在本轮改变 UTF-8 错误策略。

## 8. HTTP-003：诊断不输出 event/id 内容

不为 `SseMessage` 增加 redactor 字段：它是公开字段结构，改动会破坏结构体字面量，而且没有必要。原始 `event`、`data`、`last_event_id` 仍由调用方正常读取。

严格模式、预算失败等解码错误统一使用固定摘要 `Failed to decode SSE message data as JSON`，并继续通过 source 保存已有的安全 `JsonDecodeError`，保留种类、阶段、位置和预算信息。

Lenient 跳过日志保留 error_kind、error_stage、normalized_line、normalized_column；将原始 event/id 内容替换为 `event_present`、`event_bytes`、`last_event_id_present`、`last_event_id_bytes`，字节数来自 String::len，缺省为零。禁止输出内容、前缀或可逆编码。本轮不改变公开 SseMessage 的 Debug 派生或调用方主动打印消息的行为。

旧测试对错误字符串中含 event/id 的断言应改为安全断言。新测试同时把秘密放入 data、event、id，验证 message、Display、Debug、JSON source 及 Lenient 日志均不含秘密；同时验证错误种类、source 类型、阶段及预算失败传播仍有效。

## 9. HTTP-006：确定性的分块测试

在 `src/sse/line_decoder.rs` 的 `#[cfg(test)]` 测试模块中直接向现有 `decode_lines` 输入 `HttpByteStream`，底层使用 `futures_util::stream::iter`，每个输入元素就是一个确定的 Bytes 块；无需扩大生产 API 可见性或添加公开测试入口。

测试采用同一基准数据的单块、逐字节及每个二分切点划分，并覆盖 CR/LF 分离、UTF-8 多字节字符分离、BOM 分离、空块、恰好行上限、超限、错误后无后续输出。针对帧及 JSON 完成行为仍用公开 response API 测试，网络测试保留为传输集成证据。

已有 join/flatten helper 改为准确表达缓存输入用途的名称，如 `buffered_response_from_parts`；相关测试名称去掉跨 chunk 承诺并更新 EOF 期望。只调整直接受影响的 helper 和调用点，不做全库重命名或测试布局搬迁。

## 11. 兼容性与迁移

公共函数签名、公开结构、错误种类、feature 和依赖体系保持不变。以下行为和诊断文字有有意变化：

| 变化 | 受影响调用方 | 迁移方式 |
| --- | --- | --- |
| EOF 不再派发残帧 | 依赖宽松末帧的 SSE 服务和消费方；OpenAI Chat 的严格完成检查、Responses 的 AllowEof 流 | 服务端为每个事件写入完整空行，包含最终 done；消费方接受缺标记错误或按业务处理无新事件 EOF，不以关闭连接代替帧终结 |
| 错误消息不含 event/id；日志字段改为长度与存在性 | 解析诊断字符串或日志字段的应用和测试 | 使用错误类别及安全 JsonDecodeError source；需要业务关联时由应用在明确的数据策略下自行记录消息字段 |
| 完整 raw body 不再因 preview 截断标为不完整 | 下游结构化错误分类器 | 无 API 迁移，验证 provider_code 恢复及分类决策符合预期 |
| cached stream 保留缓存、起始 BOM 被接受 | 重复读取响应或使用 BOM 上游的调用方 | 无 API 迁移，移除不必要的绕过逻辑时另行评估，不在本轮改下游 |

不增加默认宽松开关、不发布 crate、不升级下游仓库。本方案明确描述行为修复；版本发布决策由发布阶段单独处理。

## 12. 验收与风险

1. 七项都具有可定位的代码或文档变更与验证证据，已有复现应先失败再通过。
2. raw 完整性矩阵覆盖 Content-Length 已知/未知、等于限额、超过限额、读取失败、取消和两类限额互换。
3. SSE 数据派发只发生于完整空行；未完成 done 不能成功通过 RequireDoneMarker；控制记录、重连 Last-Event-ID 和取消不回退。
4. BOM 在所有真实切块中一致处理，正文 BOM 保留，行限额不放宽。
5. 缓存和后端消费契约分别成立；SSE 自动诊断不包含原始数据、事件名或游标。
6. 双语文档、rustdoc、示例类型一致，当前 crate 的测试与项目检查通过。所有重型检查由计划的最终集成任务集中运行。

主要兼容风险是原先依赖 EOF flush 的服务端；使用明确迁移说明和完整/残帧回归矩阵控制。原始错误体完整性改正可能让下游重新识别错误码并改变重试结果，这是预期修复收益，手工核查时须展示实际 provider code。BOM 首行宽限只用于去除三个编码字节，必须验证去除后的限额。
