## 3. 方案选择与架构边界

采用在现有组件内修正合同的方案，保留客户端、惰性响应体、SSE 字节→行→记录→JSON 管线以及独立重连执行器。不新增公开 feature、公开错误种类或配置键，不升级依赖和 MSRV。这些是最小实现选择，若实际核查证明无法满足目标，应记录证据并在本轮直接相关范围内调整，而不是无限扩展。

比较过的方向：

1. **现有分层内补足策略快照和状态边界（采用）**：行为可由公开 API 回归观察，迁移面小。
2. **统一 HTTP 重试与 SSE 重连为新执行框架（不采用）**：会改变预算、取消、错误 source 与响应体生命周期，远超本轮收益。
3. **只补文档或禁止拦截器修改请求（不采用）**：不能消除实际重复 POST、帧计数及正文判断问题，还会削弱既有 API。

两个必要的内部类型新增是允许的：携带单次尝试重试决定的私有失败封装，以及标记 IPv6 重定向违规的私有错误类型。分别放入现有 `client/internal/`，不拆分其他大型模块，不引入通用策略框架。

## 4. HTTP-R01：实际请求的续试资格

### 4.1 固定外层预算，尝试内收紧资格

保留当前 `execute` 对原始请求的流程准入：原始请求未启用重试、方法不允许或 max_attempts≤1 时仍只执行一次。拦截器不会把原先不准入的调用升级成新重试流。这避免改变单次执行的 source、取消和预算合同。

已准入的重试流中，每次执行拦截器后，以 `self.options.retry.resolve(&request)` 和最终 method 重新计算是否允许继续尝试，以及最终请求的 `honor_retry_after`。初始客户端 max_attempts、max_duration、退避和错误白名单保持整次调用固定；请求级覆盖只能按既有可配置字段影响该次续试。实际 POST 在 IdempotentOnly 下失败即终止；显式最终 AllMethods 仍可允许 POST。最终 force_disable 必须终止续试。下一次从原模板克隆并重新运行拦截器，不把第一次修改累积到下一次。

如果拦截器本身返回错误，也必须按其返回时已经形成的请求快照决定该错误是否可重试，不能遗漏部分修改。发送前取消、URL 错误、响应拦截器错误、状态码错误继续保留原有领域分类。

### 4.2 私有数据传递，不给 HttpError 添加内部策略字段

建议新增 `client/internal/http_attempt_failure.rs`，私有 `HttpAttemptFailure` 包含：`error: HttpError`、`retry_allowed: bool`、`honor_retry_after: bool`。由单次尝试路径在拥有最终请求时捕获资格，再把所有后续失败附上该快照。直接单次执行将封装解出成 HttpError。所有字段和 helper 使用英文 Rustdoc。

`HttpRetryRule` 内部改为对 `HttpAttemptFailure` 决策：先检查 retry_allowed，再按固定错误白名单和 hint 处理。无需 Arc/Mutex、共享可变策略或扩展公开错误结构。`execute_once_with_context` 可返回 `Result<HttpAttemptResponse, HttpAttemptFailure>`；直接路径和内部测试同步适配，避免重复执行拦截器。

重试终态先执行现有 qubit-retry 的 `RetryError::map_error(HttpAttemptFailure::into_error)`，再交给已有 `map_retry_error`。对外直接 source 必须仍为 `RetryError<HttpError>`，保留所有重试上下文、完成诊断、错误 body、redactor 和 backend source。新增 wrapper 不得出现在公开 source 链或改变下游 downcast 类型。

成功响应与取消令牌归属沿用 `HttpAttemptExecutionContext`，不得因本次资格调整恢复已经被替换/移除的令牌。已有调用级取消仍由外层 retry executor 持有；HTTP-Q01 单独核查 SSE，不借此改写普通 HTTP 的流级取消规则。

## 5. HTTP-R02/R03：正文长度与捕获终止

### 5.1 足量捕获立即完成

保留 `max(preview_limit, raw_limit.max(1)).saturating_add(1)` 探测上限与 preview/raw 独立截断标志。每次追加后，除当前 chunk 超出可捕获长度外，还检查捕获预算是否已用满；用满且已证明所保留内容不完整时立即结束，不再等 EOF。不能简单在只读到 raw_limit 时停止，否则丢失“刚好完整”与“确有更多字节”的区分。

保留未足量时的读取错误、超时和取消行为。不得为了加速错误路径放开内存限额。测试必须以响应启动/发送完成信号协调停顿，不依赖操作系统恰好将 write 切成一个 chunk；保持服务器连接不关闭，并在成功后释放服务端任务。

### 5.2 HEAD 的长度语义

最小修正放在 `content_length_hint()`：当 `self.meta.method()==HEAD` 时返回正文长度 0；其余情况保持现有头值解析。该 helper 只提供正文聚合/错误捕获提示，不修改 headers 或 Content-Length 对外可见值。HEAD 的成功 bytes/text 得到空数据；非成功 HEAD 的 raw body 为空且不因表示长度被标为截断。

不泛化移除所有 Content-Length 预判，保留普通 GET 的提前超限保护和实际读入 ResourceBudget。304 等没有成功正文的状态遵守底层响应语义；若回归发现同类误判，限定为真实无正文语义修正，不扩大为 HTTP 解析重写。

## 6. HTTP-R04/R09：退避构造与错误字段适配

`from_config` 在读取完 raw schema 后始终调用现有 `parse_retry_backoff`。缺省 delay_strategy 仍为指数，只有选定策略的参数参与构造；不把 fixed/random 的参数自动改成策略切换信号。完全不配置时必须与 `HttpRetryOptions::default()` 等价，尤其默认抖动、延迟和倍率。

适配校验错误时使用 HTTP 真实键名：

| 失败 | HttpConfigError 相对路径 | 诊断内容 |
| --- | --- | --- |
| 指数 multiplier 非法 | `backoff_multiplier` | 倍率要求，保留安全原因 |
| 指数初始值/最大值关系非法 | `backoff_max_delay` | 同时说明 backoff_initial_delay 与 backoff_max_delay 关系 |
| random 最小/最大值关系非法 | `random_max_delay` | 同时说明 random_min_delay 与 random_max_delay |
| jitter 非法 | `jitter_factor` | 0..=1 约束 |
| 未知策略 | `delay_strategy` | 现有未知值错误 |

在构造点显式映射，不把底层字段字符串拼进 config 路径。原有 `resolve_config_error` 继续添加准确 scope。不在消息中暴露其他配置或凭据；保留既有错误种类和可保留的 source，不为本项新增公开字段。跨字段错误测试同时断精确 path 和说明涉及两个真实键名。

## 7. HTTP-R05/R06：帧边界与跨连接游标

每次读到空行都结束当前帧并清零 `current_frame_bytes`，无论是否识别出字段。只有原本 has_fields 分支产生控制记录或消息；不要新增未知字段事件。保持 BOM、EOF 丢弃残帧、JSON 预算和 done-marker 行为。

runner 继续作为跨连接 last-event-id 的所有者。对 `Dispatch(mut message)`：有 Some(id) 时更新全局游标（包括空字符串）；没有 id 时将当前全局游标克隆到该消息；再输出。对 control-only id 仍更新全局游标。`Some("")` 仍表示服务端显式重置，不得用过滤空字符串的方式恢复旧游标。直接 `HttpResponse::sse_messages()` 的单连接语义不变。

保留当前重连请求头构建方式，不把“空游标时移除 header”作为附加整改项。本次测试检查消息投影、请求游标和显式重置一致，避免为了统一样式扩大协议变更。

## 8. HTTP-R07：统一组合重定向约束

在 `HttpClientBuilder::create` 总是构造一个组合 redirect closure，捕获客户端级 ipv4_only 和 origin_policy，再委托原有 limited/default 策略维护跳数。裁决顺序：启用 SameOrigin 时先检查同源；再检查 ipv4_only 下目标 Host::Ipv6；最后交给原策略。

新增私有 `RedirectIpv6Violation`（`src/client/internal/redirect_ipv6_violation.rs`），Display 使用固定文本，不包含未经脱敏的目标值。`backend_error_mapper.rs` 像检测 `RedirectOriginViolation` 一样识别其 source，将其映射为已有 `HttpErrorKind::InvalidUrl`，保留脱敏和 reqwest source。这样不会落入默认 retryable Transport，并与初始 IPv6 URL 拒绝保持分类一致。源策略冲突优先报告现有 OriginPolicy。

本项处理客户端级 ipv4_only。请求级 ipv4_only 已文档化为 URL 校验覆盖，不借本次构造新的 per-request 后端或连接池。禁止IPv6字面量也包括 IPv4-mapped IPv6，不能因其嵌入 IPv4 而放行。

## 9. HTTP-R08：boundary 的未引用字符集

继续要求 ASCII、1..=70 字节，并保持未引用 boundary 的既有生成方式。允许字符为字母、数字以及 `'`、`+`、`_`、`-`、`.`；这是 MIME bcharsnospace 与 HTTP token 的交集。拒绝 HTTP token 独有的 `!#$%&*^`、反引号、`|~`，也继续拒绝当前未引用策略不支持的空格和 `/ :=?(),` 等字符。

直接参数与现有 Content-Type 解析出来的 boundary 使用同一个校验器，保持值一致性检查。更新错误信息及双语指南，说明是未引用且满足 MIME 的安全子集，不承诺支持所有合法 quoted boundary，不生成或重写调用方 body。

依据：[RFC 2046 §5.1.1](https://www.rfc-editor.org/rfc/rfc2046#section-5.1.1)。

## 10. HTTP-R10/R11：文案和测试进程边界

超时统一为“从异步发送前准备开始，直至收到响应头的累计期限”。覆盖 effective_headers（含 async injector）、streaming-body factory、发送、服务器等待首部；同步 request interceptor 在该 deadline 建立前执行，不能宣称它受此异步期限抢占。分别说明 connect timeout、逐次 read timeout 和 reqwest request timeout。将相关 `Write timeout` 文案改为 response-header/preparation 阶段文案，保持 HttpErrorKind 不变。

同步 README.md、README.zh_CN.md、doc/user_guide.en.md、doc/user_guide.zh_CN.md、doc/design.md、doc/design.zh_CN.md，限于本轮行为、迁移及超时说明，不重排整份文档。新增内部 Rustdoc 采用英文，消除被改代码旁的语义冲突，不借本轮逐文件风格清理。

环境代理测试采用当前集成测试可执行文件的子进程入口：父测试以 `current_exe()` 调用专用 worker test 的 `--exact` 名称，用 `Command::env/env_remove` 设置子进程环境和场景哨兵。worker 未见哨兵直接返回，避免普通 cargo test 时重复执行。父进程不使用 set_var/remove_var，不依赖其他测试持有同一锁。

子进程清除大小写 HTTP_PROXY、HTTPS_PROXY、ALL_PROXY、NO_PROXY 的继承值，按场景设置受控代理，并移除会切换 CGI 代理处理的 REQUEST_METHOD；不清空 PATH 等无关环境。分别验证 use_env_proxy=false 直连、true 经代理，后者指向可转发的本地代理，确保 NO_PROXY 不掩盖测试。父测试设置总等待上限，超时终止并回收仅该子进程，携带 stdout/stderr 报告失败，不做仓库清理操作。

## 11. HTTP-Q01：核查门与条件分支

不预设“原 token 仍取消重连”等于缺陷。普通 HTTP 已明确区分调用级 token 与单次 I/O token，SSE 可以有同类流级归属。实施时先记录源合同：原模板 token 是否控制整个 reconnect 调用、拦截后的 token 是否只控制当前 I/O、移除是否只作用于本次尝试。核查四个阶段：发送、返回响应后的读取、EOF/错误后的等待、下一次请求准入。

必须验证：替换 B 后取消 B、替换 B 后取消 A、移除 A 后取消 A、无替换取消 A。用受控响应/回调信号选择阶段，不用时间巧合判定归属。只要行为符合可证明的流级/尝试级合同，即记录“疑点排除”、保留现有行为，并在重连文档解释两层归属。

如果发现当前 I/O 忽略实际绑定的 B、Cancelled 被错误重连等明确矛盾，才在现有 runner/runtime/context 边界修正。单次替换 token 不自动成为后续所有尝试的永久 token；不添加公共“取消模式”选项。若要改变原模板 token 的流级所有权，必须先给出其与现有合同矛盾的证据；不能仅因 Q01 被采纳就修改。若没有合同证据支持改变该归属，本轮以行为刻画测试与准确文档收束，不擅自扩大语义。
